# Flyswamp — контекст для Claude Code

Научная симуляция-игра: муха с реальным коннектомом MaleCNS v1.0 в 3D-болоте учится избегать росянок. Цель — чтобы поведение вытекало из проводки и опубликованных моделей, а не из формул. Обзор для людей: [docs/PROJECT.md](docs/PROJECT.md). Реестр «что откуда и что проверено»: [docs/SCIENCE.md](docs/SCIENCE.md). Фазы и гейты: [docs/ROADMAP.md](docs/ROADMAP.md). Исходный обзор исследования (артефакт пользователя): https://claude.ai/artifact/VYzwifqpYcQra114Lfy3zk

## Правила проекта

- **Наука, а не подгонка.** У каждого компонента есть статус в `docs/SCIENCE.md`: данные / метод / проверено / дизайн / каркас. Поменял компонент — обнови реестр.
- **Фаза закрывается гейтом из `docs/ROADMAP.md`.** Числа в документах берутся только из скриптов `validation/`, результаты лежат в `validation/results/*.json`.
- **Не выдумывать API, числа и ссылки.** Если не знаешь, так и пиши: «не знаю».
- **Численные упрощения проверять в том режиме, где они будут работать.** Шаг 0,2 ms прошёл гейт на FlyWire, но срывает MaleCNS.
- **Движок `web/src/sim/lif.js` по умолчанию обязан оставаться точным портом Shiu et al. 2024.** Проверка — `npm test` плюс сравнение из `validation/`. Расширения (адаптация и т. п.) — только опциональными параметрами, выключенными по умолчанию.

## Пользователь

- Язык русский, технические термины на английском.
- Плотно, без вступлений и резюме, без лести. Несогласие — сразу.
- Решения: 2–3 варианта с trade-offs и одна нестандартная опция.
- Сначала короткий план, потом код. Трогать только то, о чём просили. Слабые допущения называть до работы.
- Повторяющуюся ручную работу оформлять скриптом.

## Окружение

В git лежит код, документы, данные игры `web/public/data` (13 МБ), эталоны и результаты `validation/`. Не в git:
- `.cache/malecns` — сырые данные MaleCNS, 1,1 ГБ;
- `.cache/graphs` — упакованные графы;
- `.cache/ref` — клоны эталонных репозиториев;
- `.cache/flybody`;
- `.venv-ref`.

- **SessionStart hook** (`.claude/hooks/session-start.sh`) в веб-сессиях ставит `web/node_modules` и `pipeline/requirements.txt`. Этого хватает для `npm test`, игры и пайплайна.
- **`scripts/setup.sh`** восстанавливает всё остальное на закреплённых коммитах: эталонные репозитории, `.venv-ref` (Brian2 2.9, numpy < 2.3), данные MaleCNS, графы `flywire630` и `malecns_min1`. Запускать перед работой с `validation/` или `pipeline/build_graph.py`. Отдельные шаги: `scripts/setup.sh refs venv`.
- **Память 16 ГБ.** Таблицу весов MaleCNS (1 ГБ feather, 152 M строк) читать один раз, через `memory_map` и фильтры pyarrow. Эталон Brian2 занимает ~3 ГБ на воркер: не больше 3 воркеров и ничего тяжёлого параллельно, иначе OOM-killer убьёт прогон.
- **Скорость.** Эталон Brian2: ~13 мин на 30 проб на 3 ядрах. Наш движок: FlyWire — 0,6× реального времени, целый MaleCNS — 9 с на секунду симуляции (`DENSE=1`).

Ловушки, на которые уже наступили:
- **`pkill -f шаблон`** убивает и собственный шелл, если шаблон есть в его командной строке. Используй `pgrep`, затем `kill PID`.
- **ID FlyWire 18-значные** и не влезают в float64. Храни их строками. Регулярка — `\b7205\d{14}\b`: `\d{13}` их обрезает.
- **В `.venv-ref` стоит pandas 3:** пропуски в строковых колонках становятся NaN. JSON писать с `allow_nan=False`, записи собирать из обычных списков.
- **Brian2 делает `v` и `g` условной записью при `(unless refractory)`:** вход в рефрактерный нейрон теряется. Движок это повторяет, и тест это проверяет.

## Команды

```bash
cd web && npm test                                   # 13 тестов
cd web && npm run dev                                # игра
node scripts/experiment.mjs 15 4                     # headless-эксперименты прототипа
node validation/run_lif.mjs .cache/graphs/flywire630 validation/reference/sugar_150hz.json out.json   # движок на эталонном стимуле
node validation/compare.mjs a.json b.json            # статистическое сравнение, гейты P1
node validation/offset_test.mjs .cache/graphs/malecns_min1 malecns out.json 5    # бенчмарк затухания
DENSE=1 node validation/malecns_sugar.mjs .cache/graphs/malecns_min1 150 5 out.json   # сахар → MN9 на MaleCNS
LIF_PARAMS='{"wSyn":0.2}' ...                        # параметры движка для любого скрипта validation/
```

## Где остановились

- **P0 и P1 закрыты.** Движок совпадает с Brian2-эталоном и с результатами авторов: 0 отличающихся нейронов на 100, 150, 200 Hz.
- **P2 в работе**, подробности — в `docs/SCIENCE.md`, раздел P2.
  - Сделано: граф MaleCNS (`pipeline/build_graph.py`), знаки NT по конвенции Shiu, перенос наборов экспериментов на MaleCNS (`validation/map_flywire_to_malecns.py`), бенчмарк затухания, развёртка `w_syn`.
  - Сахар → MN9 воспроизводится: 65–97 Hz против 59–83 Hz у FlyWire.
  - Затухание не проходит: петли VNC защёлкиваются стохастически при любом `w_syn`, где MN9 отвечает. Это IN10B003 ↔ IN08B004 и DNg33 ↔ AN27X013/AN09A005 → DLMn.
  - Мозг без VNC срывается целиком при `w_syn` 0,275.
- **Ждём решения пользователя** по варианту P2 (`docs/ROADMAP.md`):
  1. мозг и VNC раздельно;
  2. адаптация спайков (SFA) с совместной калибровкой и hold-out — рекомендовано;
  3. conductance-синапсы и масштаб по объёму нейрона;
  4. проверить по литературе, не реальные ли это бистабильные модули.
- **Следующие шаги после решения:**
  - набор бенчмарков: горькое гасит сахар через `neu_bitter` со второй частотой Poisson; вода; затухание по сидам;
  - контроль с перемешанной проводкой при сохранении степеней;
  - WASM SIMD или WebGPU для скорости.
- **Игра пока на прототипной rate-модели** (`web/src/sim/brain.js`). Спайковый движок подключается в фазах P4–P5.
