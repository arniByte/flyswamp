# Научный реестр

Для каждой части симуляции указано, откуда она взята и насколько ей можно доверять. Статусы:

- **данные** — извлечено из опубликованного датасета без подгонки;
- **метод** — опубликованная модель, перенесённая как есть;
- **проверено** — наш код сверен с эталоном численно, отчёт лежит в `validation/`;
- **дизайн** — наше решение ради игры, биологией не подтверждено;
- **каркас** — временная заглушка, её заменит фаза из [ROADMAP](ROADMAP.md).

## P1: движок LIF против эталона Shiu et al. 2024

Эталон — их `model.py` без изменений (Brian2 2.9.0, numpy 2.2.6), граф FlyWire 630 из их репозитория. Стимул — 21 сахарный GRN из их `example.ipynb`, Poisson 150 и 100 Hz, 30 проб по 1 с. Наш движок: те же уравнения, точное интегрирование линейной системы, порядок шага Brian2 (state update → threshold → synapses → reset). Единственное отличие — нейроны у покоя (|v − v₀| и |g| < 10⁻⁶ mV) не пересчитываются. Тест `web/test/lif.test.js` проверяет, что это не меняет ни одного спайка.

Сравнение статистическое: генераторы случайных чисел разные, поэтому спайки не совпадают, а совпадать должны распределения.

- Совпадение средних частот (Pearson) сравнивается с потолком шума самого эталона (split-half).
- Для каждого нейрона считается Welch z с поправкой Бонферрони.
- Отдельно сравнивается MN9 — моторный нейрон хоботка, главный выход в их работе.

Скрипты: `validation/shiu_reference.py` (эталон), `validation/run_lif.mjs` (наш движок), `validation/compare.mjs` (статистика).

Воспроизвести (нужен клон репозитория Shiu в `$SHIU_REPO`; Brian2 2.9 требует numpy < 2.3):

```bash
python -m venv .venv-ref && .venv-ref/bin/pip install brian2==2.9.0 "numpy<2.3" pandas pyarrow joblib
cd validation
../.venv-ref/bin/python pack_flywire630.py                                   # граф → .cache/graphs/flywire630
../.venv-ref/bin/python shiu_reference.py sugar 30 3 reference/sugar_100hz.json 100   # ~13 мин на 3 ядрах
node run_lif.mjs ../.cache/graphs/flywire630 reference/sugar_100hz.json results/lif_sugar_100hz.json
node compare.mjs results/lif_sugar_100hz.json reference/sugar_100hz.json
```

Результаты (`validation/results/*.json`, 30 проб на каждой стороне):

| Сравнение | Нейронов | Pearson | Split-half, внутри / между | MN9, Hz | Отличаются по Бонферрони | Гейт |
|---|---|---|---|---|---|---|
| наш движок против Brian2 2.9, 100 Hz | 420 | 1.000 | 0.999 / 0.999 | 68.3 ± 5.3 против 68.1 ± 4.6 | 0 | PASS |
| наш движок против авторского `sugarR_100Hz.parquet` | 416 | 1.000 | 0.999 / 0.999 | 68.3 ± 5.3 против 67.0 ± 6.7 | 0 | PASS |
| наш движок на 200 Hz против авторского `sugarR.parquet` | 455 | 1.000 | 1.000 / 1.000 | 92.8 ± 4.4 против 93.3 ± 3.2 | 0 | PASS |
| наш движок против Brian2 2.9, 150 Hz | 437 | 1.000 | 0.999 / 1.000 | 83.9 ± 5.0 против 83.2 ± 5.3 | 0 | PASS |
| контроль: Brian2 2.9 на 150 Hz против авторского `sugarR.parquet` | — | — | — | 83 против 93 | сотни | FAIL, как и ожидалось |

Что выяснилось по дороге:

- **Проверка поймала ошибку в первой версии порта.** В Brian2 флаг `(unless refractory)` делает `v` и `g` условной записью. Синаптический и Poisson-вход в нейрон, который рефрактерен или спайкнул в этом шаге, теряется. Это видно в сгенерированном коде: `add.at(g, post[not_refractory], w[not_refractory])`. Первая версия порта копила такой вход, и MN9 выходил 105 Hz вместо ~84 Hz, а значимо отличались 339 нейронов. После исправления отличий ноль.
- **Авторский пример `sugarR.parquet` посчитан при 200 Hz, а не при 150 Hz** из `model.py`. Сахарные GRN в нём дают ~197 Hz. Это ровно то, что даёт Poisson 200 Hz за вычетом событий, попавших в шаг спайка. Наш движок на 200 Hz совпадает с файлом по всем нейронам. На 150 Hz расхождение большое (MN9 84 против 93 Hz).
- **Версия Brian2 роли не играет.** Код state update, PoissonInput и синапсов в Brian2 2.5.1 (версия статьи, `environment_full.yml`) и 2.9.0 совпадает построчно.
- **Скорость.** Полный FlyWire 630 (127 400 нейронов, 14,7 M связей) на одном потоке Node считается в 0,55–0,77× реального времени при шаге 0,1 ms. Эталон на Brian2 с numpy-бэкендом: 30 проб за 216 с на 3 ядрах, включая сборку сети в каждой пробе. C++ standalone-режим Brian2 я не запускал.
